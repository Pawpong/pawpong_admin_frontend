# 검증 방법

Node 22.15 이상, pnpm 9.15.4.

```sh
pnpm test:contract:update
pnpm test
pnpm typecheck
pnpm build
pnpm lint
```

`test:contract:update`는 공개 개발 OpenAPI를 읽어 관리자·공용 업로드/로그아웃 관련 스키마를 저장한다. URL 또는 로컬 JSON 경로를 인수로 지정할 수도 있다. 민감한 인증 정보는 필요하지 않다.

`pnpm test`: 네트워크 없는 회귀 테스트와 API 계약 검사를 실행한다. 2026-09-06 `node --test tests/*.test.mjs` 25개 통과, 빌드/타입 검사 및 변경 파일 ESLint 통과. 계약 검사는 131개 호출 / 관리자 operation 119개 연결을 확인하지만, 배포 대기 중인 accountType query 1건이 현재 운영 명세에 없어 전체 명령은 실패한다. 기존 전체 lint 18 errors / 1 warning은 gaps.md 참고.

브라우저: Orca에서 개발 서버를 열고 명세로 생성한 mock 응답을 실제 API 모듈에 주입해 전체 32개 페이지를 데스크톱 및 폭 390px 프레임에서 순회했다. 런타임 예외, 콘솔 오류, 로딩 실패 문구, 문서 가로 넘침을 확인했다. 테스트용 계정·데이터는 운영 데이터가 아니다.

별도 상호작용 확인: 빈 검색어 저장 차단, 유효 검색어 저장의 mock POST 도달, 이메일 sandbox 미리보기, 필수 이메일 정보 없는 발송 차단, 콘테스트 항목 입력 화면. API 요청의 false·0 값 보존 및 raw HTML 응답은 자동 회귀 테스트로 확인한다.

실제 서버 검증에 필요한 후속 작업: 테스트 관리자 계정으로 로그인하여 역할별 권한, CRUD 후 재조회, 실제 파일 CDN 접근, 이메일/푸시/알림톡 수신, 배포 후 갱신·로그아웃을 검증한다. 이 단계는 완료되지 않았다.

연결 확인: 로컬8080/dev-api/api 서버 모두 응답. 개발용 동일 출처 프록시를 적용한 뒤 브라우저의 실제 인증 오류 응답 수신을 확인했다. 인증되지 않은 401은 로그인 필요 상태이며 성공한 데이터 조회로 계산하지 않는다.

## 2026-09-06 검증

- 데스크톱 및 390px 프레임에서 32개 화면을 명세 mock으로 순회: 런타임/콘솔 오류, 문서 가로 넘침, 로딩 실패 없음.
- 검색 응답을 450ms/20ms로 지연해 순서가 바뀌어도 최신 결과 유지. URL 뒤로가기 복원, 검색 시 페이지 1로 초기화, 검색 및 미제출 초안 초기화 확인.
- 목록 조회 오류 주입 후 오류 표시 및 다시 시도 성공 확인.
- 운영 브라우저의 기존 로그인 세션을 `/auth-admin/refresh`로 정상 갱신. 토큰은 출력하지 않고 같은 브라우저 내부에서만 사용.
- 운영 GET 12건 모두 200: 관리자 프로필, 플랫폼 통계, 브리더 통계, 브리더 목록, 존재하지 않는 이름 검색(0건), 지역 검색, 시스템 상태, 알림 목록/통계, 인기 검색어, 커뮤니티 신고, 이메일 미리보기 카탈로그.
- 운영 데이터 수정, 계정 flag 변경, 실제 메시지 발송은 수행하지 않음. 운영 CRUD 전반의 완료 증거로 해석하지 않는다.
