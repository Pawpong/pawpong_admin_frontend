# 놀이터 결제 어드민

`/billing`에서 서버 상품 카탈로그, 기능별 이용권 정책, 구매 원장, 감사 이벤트를 관리한다. 백엔드 `.kiro/specs/in-app-purchase/api-contract.md`에 합의한 `/api/iap-admin` 계약을 사용한다.

상품 생성은 기본 비활성·판매 중지·스토어 미등록이다. 운영자가 상품 코드, 스토어 ID, 소모성/비소모성/구독 유형, 혜택·공통 creditKey·수량, 판매 여부를 설정한다. 가격과 실제 구독 기간은 스토어에서 관리한다. 스토어 상품 등록/심사 없이 내부 카탈로그만으로 판매되지 않는다. 기존 판매 상품의 지급 정의 변경은 서버가 거절하며 원장을 보존하기 위해 삭제는 보관 처리로 동작한다.

모든 변경은 사유를 남긴다. 기능별 dailyFreeLimit/creditCost/creditKey/enabled와 미래 기능의 비활성 정책을 설정할 수 있다. 구매·감사 내역은 회원/상품/스토어/기간으로 조회하고, 상세에서 권한 회수·재지급 사유와 타임라인을 확인한다. 권한 조치는 스토어 환불 실행과 별개로 표시한다.

실제 상품·가격·판매 정책은 이 변경에서 운영에 등록하지 않았다. 운영 DB·서버 및 스토어 심사 제출은 수행하지 않는다.

## 검증

- 타입체크, 전체 Node 테스트 42개, Vite 빌드, 변경 파일 ESLint 통과. 전체 lint의 기존 다른 기능 오류는 별개다.
- 실제 백엔드 Swagger의 IAP 관리자 11개 작업을 계약 fixture에 반영했다. API 호출 158개 불일치 0, 필수 관리자 작업 146/146개 연결을 확인했다.
- 원래 계약 검사에서 누락됐던 약관 관리 6개 작업을 `/content/terms`에 연결했다. 조회·상세·초안 생성·내용 수정·별도 활성화·비활성 버전 삭제를 지원한다. 새 버전 저장은 항상 `activate:false`이며 테스트에서 임의 활성화 값도 무시됨을 확인한다.
- AI 필터는 기존 multipart 업로드를 사용하므로 미사용 직접 S3 URL 발급 작업 1개만 계약 커버리지에서 명시적으로 제외한다. 나머지 누락과 실제 호출 불일치는 계속 실패 처리한다.
- Orca의 `iap.localhost:5183`에서 실제 Nest API와 격리 MongoMemoryReplSet을 연결했다. 테스트 상품 활성화, 수정 사유 필수 검사, 일일 무료 4/이미지 비용 2 정책 반영, 실제 구매 원장 조회, 회수(잔액 8→3), 재지급(3→8), 사유·행위자 감사 기록을 확인했다.
- 약관 초안은 비활성으로 저장되며 조회·수정→활성화→기존 테스트 버전 재활성화→초안 삭제까지 로컬 브라우저에서 검증했다. 활성 버전 삭제는 비활성화되어 있다.
- 외부 스토어 응답만 fixture로 대체했으며 실제 Apple·Google 청구/스토어 연동 완료를 의미하지 않는다. 실제 환경 검증은 새 RN 빌드·상품 등록·서버 설정 후 필요하다.
